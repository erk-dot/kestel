If a newer form went out for the same event, only the newest form counts. Earlier answers are kept below each event so you can see what was replaced.

What the statuses mean

  • AvailableThe newest form for this event recorded the player as available.
  • UnavailableThe newest form recorded the player as not available.
  • Not submittedNo answer on the newest form yet, and it is still open. There is still time.
  • Not submittedNo answer on the newest form, and it has closed. Contact the team manager.
Build notes

This prototype is not private. All of the demo data sits in one public file, data.json, which anyone can open in a browser. The player code only filters what is shown on screen; it does not protect anything. That is acceptable here only because every record is fake. Real player data must not be loaded until a server-side access check exists (see below).

The problem it addresses

Tournament availability is collected with online forms. There is no confirmation email, and new versions of a form go out during the season, so a family can believe they responded while the record shows the player as unavailable because a later version was never filled in.

Where the records would come from

  • Each form's responses already land in a spreadsheet (Google Forms writes to a Google Sheet; Microsoft Forms exports to Excel).
  • The team manager would update the records: export or link each form's response sheet, then run a small merge step that keeps the newest form version per player per event and files older answers under "Earlier versions".
  • The page shows when the records were last updated, so nobody mistakes an old snapshot for the current state.

Matching responses to players

Forms that ask only for a typed name and birth year make matching fragile: one typo can make a submitted answer look like "Not submitted". Each row shows what it was matched on so mismatches are visible. A real version should give each player a stable ID or code that the form asks for.

Planned access method for real data

  • A Cloudflare Pages Function checks the family's code on the server and returns only that player's rows.
  • Records live in Cloudflare KV, not in a public file, so no one can download other players' data.
  • Codes would be issued per player by the team manager and could be reset if shared.
